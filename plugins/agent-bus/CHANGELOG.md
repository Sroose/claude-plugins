# Changelog — agent-bus

## 0.2.1 — 2026-10-13

- **Display labels no longer borrow another session's name.** `user_prompt_submit.py` (`sessionTitle`) and `statusline_fragment.py` match on `session_id` only. Their unique-hostname fallback had no `host_cwd` check — contrary to the 0.2.0 entry below, which said they used "the same resolution as everything else" — so on a Mac a single registration on the shared hostname (even one with a long-expired lease) became the title of every unregistered native session, whatever its directory. Seen in the field: sessions in unrelated directories all labelled `<OTHER-AGENT>-<slug>`. The fallback exists for a watcher holding a stale `session_id` after `/resume`; these scripts always receive the current one, so they never needed it. Trade-off: after a `/resume` the label stays blank until `agent-bus register <NAME>` refreshes the entry's `session_id` (auto-rebind leaves a same-hostname entry untouched).

## 0.2.0 — 2026-09-01

Five field failures, all rooted in the same wrong assumption: that `socket.gethostname()` identifies a session. It does for containers (each gets a unique hostname) but **every native session on one Mac shares a hostname**, so to the bus they were all the same agent — and a registry file was treated as proof that somebody was listening, which it never was.

- **Heartbeat leases on registrations.** `register` (and hook/watcher auto-rebind) now writes `instance` (random per registration) and `heartbeat_at`; the session's watcher binds to that `instance` and refreshes the timestamp every ~60s from a daemon thread (needed because the `inotifywait`/`fswatch` backends block inside a read and never reach an event loop). No refresh for 300s = the session is dead. `register` auto-reclaims a name whose lease expired, printing a loud notice (previous container, host_cwd, how long ago it expired) instead of demanding a user-confirmed reclaim for entries that had been dead for months. `send` now warns when the target *is* registered but its lease expired — previously the absence of the "no session registered" warning was falsely reassuring and senders blind-retried into dead names. `list` shows lease freshness. A watcher that finds its entry gone or re-registered under a different `instance` stops heartbeating (it must not vouch for a registration it no longer owns) but keeps watching. Entries from 0.1.x carry no lease: they are "unknown", handled exactly as 0.1.5 handled them (conservative refuse), so a concurrently-running 0.1.5 session can't be reclaimed out from under itself during a rollout.
- **`SessionEnd` unregisters only its own entry.** It matched on hostname, so on a Mac *any* session's clean exit deleted whichever entry shared that hostname — a bystander `/clear` silently unregistered a long-running agent. It now deletes only the entry whose `session_id` equals the hook input's. Entries orphaned by a `/resume` (which renumbers `session_id`) are no longer deleted here; they expire via the lease instead, which is a measured liveness signal rather than a guess.
- **Unambiguous `whoami`.** Resolution is now `session_id` match → *unique* hostname match → nothing. The hostname fallback stays because a watcher spawned before a `/resume` holds a stale `session_id` in its env, but it is only trusted when it resolves to one entry. `whoami` prints the candidates and a re-register hint instead of answering as whichever entry the directory glob returned first.
- **One watcher per host/container.** A starting watcher SIGTERMs the pid in `log/watcher-<hostname>.pid` (only if it's alive *and* `ps -p <pid> -o command=` mentions `watch.py`/`agent-bus` — pids get recycled, and macOS has no `/proc`), then claims the file. Orphaned watchers used to pile up: a live `watcher.log` showed ~9 pids reacting to each message, two of them emitting the same one, i.e. duplicate notifications in the receiving session.
- **Stable `host_cwd`.** It was `$HOST_CWD or os.getcwd()`, evaluated at call time, so a session that `cd`-ed after registering addressed a different `cwd-memo` than the one it registered under (two memos for one agent, in two directories, existed in the wild). `SessionStart` — which also runs on `/resume`, hence always fresh and pre-`cd` — now records `session-cwd/<session_id>.json`, and resolution is `$HOST_CWD` → that record → `os.getcwd()` only as a last resort. `SessionEnd` removes its own record; `init_dirs()` sweeps ones older than 30 days.
- **Deferred-`Monitor` guidance.** In current Claude Code builds `Monitor` is a *deferred* tool — invisible until loaded — so agents concluded it didn't exist and fell back to running `agent-bus watch` as a background Bash task. Background Bash only notifies on process *exit* and the watcher never exits, so messages were captured to a file and silently swallowed forever. `register`'s output, the SessionStart guidance, SKILL.md, PROTOCOL.md and DESIGN.md now all say: load it with `ToolSearch` (`select:Monitor`), never substitute a background Bash task, and if `Monitor` is genuinely unavailable tell the user instead of improvising.

- **A live registration can no longer be taken silently.** The conflict check only guarded `container != SELF_HOST`, so the same-hostname path kept a "same container, fine — refresh below" fall-through: on a Mac *any* native session could `register` a name a live session already held, rewriting its `session_id` and `instance` while the displaced session's watcher quietly released the lease on the instance change — the very configuration this release exists to fix. Claiming is now one ordered decision (`claim_decision`): **1** our own `session_id` → refresh; **2** same hostname *and* same non-empty `host_cwd` → refresh, printing the `session_id` change (this is the `/resume` path, where the sid is renumbered but the host directory is not); **3** stale lease → reclaim with the loud notice (now reachable for same-host-different-directory too, not just cross-host); **4** legacy entry → refuse; **5** fresh lease → refuse (exit 4), stating whether the holder is another host or another directory here, and that the lease expires within 300s if it is genuinely dead. `host_cwd` is the discriminator because hostname equality is not evidence of ownership; it is the same lineage invariant the cwd-memo auto-rebind already relies on, and an unknown `host_cwd` on either side never counts as a match. New **`register --force <NAME>`** overrides a refusal — the user-confirmed reclaim the docs demanded but never provided — and always prints what it displaced. The same directory check now also gates `my_entry()`'s unique-hostname fallback in `bus.py` and `watch.py`, so a bystander session no longer answers `whoami` as somebody else's agent (a pre-`/resume` watcher still resolves, via its old sid's session-cwd record, to the same directory). Residual and documented: two native sessions in the *same* host directory remain indistinguishable, which is outside the one-agent-per-host-directory contract.
- **Compaction resilience.** Compaction kills neither the Monitor task nor `watch.py` — it erases the *model's* knowledge that they exist, after which the agent re-registers or starts a second watcher that then fights the incumbent for the pidfile. So the state is now both re-derivable and re-injected. New **`agent-bus status`**: one allowlist-clean call printing registration (or `ambiguous`/`unregistered`) with sid, instance and lease, the watcher's pid and liveness (`ps`-cross-checked, and only ever called dead when `ps` positively names a different process), the pending-message count, and a one-line verdict naming the single next action; always exits 0, because a diagnostic that exits non-zero reads as "the bus is broken". And the `SessionStart` hook — which also fires with `source=compact` — now always resolves this session's registration and appends an `[agent-bus live state]` block: name, lease, watcher pid/liveness, and an explicit "do not re-register, do not start a second watcher if one is alive". Ambiguous identity gets its own variant; unregistered sessions get nothing.
- `user_prompt_submit.py` (the `/resume` picker title) and `statusline_fragment.py` now use the same session_id-first resolution as everything else, instead of labelling every native session on a Mac with whichever registration the directory listing returned first. The statusline fragment now really does read `session_id` from CC's session JSON, as DESIGN.md had claimed.

Also: the hooks honour `$BUS_ROOT` like `bus.py`/`watch.py` already did, so the whole plugin can be exercised against a throwaway bus directory.

## 0.1.5 — 2026-05-30

- **Timestamps on message lines.** Outbound echo and inbound notification now show the message's send-time as `[HH:MM:SS]` in **local time**. The payload's `ts_iso` stays UTC (canonical); only the on-screen line converts (via `localtime()` / `datetime.fromtimestamp(ts)`). Helps follow long-running bus exchanges on scrollback, where Claude Code has no built-in per-message timestamp. Caveat: "local" = the timezone of the process rendering the line — host-native sessions show the Mac's local time; sessions inside a UTC container show UTC unless the container's `TZ` is set.
- **Distinct direction emojis.** Outbound `📤 → to X  [ts]: …`; inbound `📥 ← from X  [ts] (id=…):`. Replaces the visually-similar `📨`/`📤` pair — now double-coded (distinct tray icon + arrow). Docs, hook guidance, and PROTOCOL examples updated to match.

## 0.1.4 — 2026-05-28

- **Added a `bin/agent-bus` launcher** (on the Bash tool's PATH while the plugin is enabled). All operations are now invoked as a clean, statically-analyzable command — `agent-bus register OBSIDIAN`, `agent-bus send CODE "..."`, `agent-bus watch` — instead of the 0.1.3 `BUS=$(find …); python3 "$BUS" …` resolver. That resolver could **never** be matched by the permission allowlist (leading assignment + `$(…)` → "cannot be statically analyzed"), so guarded/limited-permission agents got a prompt on every call — and a prompt mid-turn can corrupt a guarded agent's transcript. With the launcher, allowlist `Bash(agent-bus:*)` and calls are prompt-free.
- SKILL.md, PROTOCOL.md, the SessionStart guidance, and the register-printed Monitor command all now emit bare `agent-bus …` commands. The `$(find …)` form remains documented only as a fallback for when the launcher isn't on PATH.
- The launcher resolves its sibling `bus.py`/`watch.py` by its own location (no find in the common case), falling back to a cache-scoped find.

## 0.1.3 — 2026-05-28

- **Dropped the `~/.claude/bus/` script symlinks entirely; helper is now resolved at call time.** The symlink approach (0.1.1 relative-target fix included) had a fatal flaw: a single shared `~/.claude/bus/bus.py` link can't point at both a container's and the host's plugin copy at once, and the link-repair logic lived *inside* `bus.py` — unreachable when you invoke `bus.py` *through* a dangling link (circular). SKILL.md, PROTOCOL.md, the SessionStart hook, and the register-printed Monitor command now resolve the script via `find ~/.claude/plugins/cache -path '*agent-bus*/skills/agent/bus.py' | sort -V | tail -1` — newest installed version, caller's namespace, nothing cached, nothing to dangle.
- The `find` is **cache-scoped** on purpose: a blanket `~/.claude` search also matches the marketplace repo clone under `plugins/marketplaces/…` (no version dir), which sorts last and would be picked wrongly.
- SessionStart no longer maintains symlinks; it injects guidance + auto-rebinds from cwd-memo as before.

## 0.1.2 — 2026-05-28

- **Symlinks at `~/.claude/bus/` are now relative.** Previously they stored an absolute target (e.g. `/home/claude/.claude/plugins/.../bus.py`), which broke when `~/.claude` is a shared bind-mount between a Docker container and the host — the absolute path is only valid in one namespace, so a session in the other namespace (or a native host session reusing a container-written link) failed with "no such file." Relative targets resolve correctly from both namespaces since link and target share the `~/.claude` root. Affects the SessionStart hook and `bus.py register`.

## 0.1.1 — 2026-05-20

- **Watcher startup is now deterministic.** The declarative `monitors/` entry has been removed; `bus.py register` now prints the exact `Monitor` tool invocation in its stdout, and `SKILL.md` instructs the agent to call it after every successful register. Previously the declarative `when: "on-skill-invoke"` trigger fired inconsistently — some sessions never got a live watcher and silently dropped messages.
- Added `~/.claude/bus/watch.py` to the stable-symlink set maintained by SessionStart and `bus.py register`.
- Removed redundant `version` field from `.claude-plugin/marketplace.json`'s plugin entry — `plugin.json` is the single source of truth.

## 0.1.0 — 2026-05-19

Initial release.

- `/agent register|unregister|whoami|list|ask|send|inbox|read|archive` subcommands
- Container-hostname-based session identity (stable across `/resume`)
- `cwd-memo` so the watcher auto-rebinds the prior name on `/resume` (no user action needed)
- Pre-filtered watcher: notifications only arrive for messages addressed to the registered name
- Pre-formatted notifications (full body, no JSON parsing required by the receiver)
- Send-time warning when target name has no live listener
- Backlog replay: messages that arrived before registration are surfaced on `/agent register`
- Auto-unregister on clean session exit; preserves `cwd-memo` for next session
- SessionStart hook maintains `~/.claude/bus/bus.py` symlink for stable invocation path
- File watcher selects best available backend: `inotifywait` → `fswatch` → shell-poll
- Optional statusline integration via `statusline_fragment.py`
- Diagnostic log at `~/.claude/bus/log/watcher.log`
